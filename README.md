# Короче

Социальная сеть, которую собираем по маленьким кускам. Стек: ванильные JS-модули, HTML5, CSS3. Сборщик не нужен, модули грузятся нативно через `<script type="module">`.

## Запуск

ES-модули не работают с `file://`, поэтому нужен локальный статический сервер. В репозитории есть `serve.ps1` (PowerShell, без установки зависимостей):

```powershell
powershell -ExecutionPolicy Bypass -File .\serve.ps1
```

Открой http://localhost:8080. Если позже поставишь Node или Python, можно использовать `npx serve .` или `python -m http.server 8080`.

## Правила имён и организации

- Один файл, одна ответственность. Если файл вырос больше ~150 строк, делим.
- Имена файлов: `kebab-case` и по роли: `posts-service.js`, `post-card.js`, `feed-view.js`, `wall-view.js`.
- Фабрики со состоянием и зависимостями называются `createXxx` (`createPostsService`, `createFeedView`).
- Чистые функции рендера называются `renderXxx` (`renderPostCard`, `renderAvatar`).
- Сервис является единственным местом, которое меняет свою часть состояния через `store.setState`.
- Представление (`*-view.js`) компонует компоненты и возвращает `{ html, mount }`.
- `mount()` возвращает функцию очистки (отписка + снятие слушателей); роутер вызывает её при уходе со страницы.
- Весь пользовательский текст перед вставкой в HTML проходит через `escapeHtml`.
- Зависимости передаются явно, без глобальных переменных.

## Сейчас работает

- регистрация и вход только по юзернейму и паролю (без почты и телефона), галочка «Запоминать и не выходить» удерживает сессию после перезагрузки;
- стартовые аккаунты удалены: все пользователи появляются только через регистрацию;
- при регистрации случайная стартовая аватарка из `assets/avatars/`;
- общая лента и публикация постов с вложениями: фото, ссылка, рисунок;
- ХАЙП вместо лайков, значок XD и теги `#вот` в тексте постов;
- удаление постов;
- широкий макет на компьютере: контент растягивается почти на весь экран, а посты на больших экранах раскладываются в несколько колонок;
- переключатель светлой и тёмной темы, логотип и аватарки меняют цвет;
- кнопка-снежинка рядом с темой включает и выключает снегопад, выбор сохраняется после перезагрузки;
- вкладки внизу экрана в порядке: профиль, правила, лента, чат, медиа, музыка, идеи и админ панель только для @murs (активная подсвечивается);
- роль «Создатель» у @murs: в профиле есть бейдж, создатель может удалять любые посты и редактировать блок «Новости»; остальные удаляют только свои посты;
- «Чат»: личные сообщения по @username, список переписок и соглашение перед первым входом; сообщения хранятся зашифрованными (AES-GCM), расшифрованный текст живёт только в памяти. Новые сообщения шифруются общим ключом приложения, поэтому собеседник их видит; старые сообщения открываются ключами аккаунтов;
- «Медиа» загрузка фото и видео с превью и просмотром, «Музыка» загрузка аудио с плеером; при загрузке можно задать название и превью, у медиа и треков есть ХАЙП;
- в профиле можно нажать на аватар и загрузить картинку или нарисовать его, баннер можно только нарисовать, а ещё можно написать «О себе»;
- раздел «Мои устройства»: устройство, с которого зарегистрирован аккаунт, становится основным, остальные пускаются только после галочки на основном, иначе показывается плашка «Ожидается подтверждение устройства на аккаунте»;
- страницы пользователей `/wall/:userId`, своя стена с формой публикации; писать можно на любой стене, пост сохраняется на ней и показывается с указанием автора;
- ники `@username` в постах, сообщениях и на страницах пользователей являются ссылками на профиль;
- вокруг аватарок тонкое кольцо: зелёное для онлайна, серое для офлайна, видно в обеих темах; онлайн определяется по времени последнего визита из Supabase; в светлой теме зелёный `#16a34a`, в тёмной `#4ade80`;
- новые посты и сообщения подтягиваются из Supabase каждые 3 секунды без перезагрузки страницы;
- сохранение состояния в `localStorage` и синхронизация с Supabase, пароль хранится только как соль + SHA-256.

## Supabase

Проект подключён к Supabase через REST без SDK и сборщиков. URL и публичный ключ лежат в `src/config/supabase.js`. Всё состояние приложения хранится в одной строке таблицы `public.koroche_state` в поле `data` типа `jsonb`.

Перед первым запуском выполни `supabase/schema.sql` в **SQL Editor** в панели Supabase. Политики в файле открыты для `anon`, потому что вход пока локальный и Supabase Auth не используется. Это прототип: публичный ключ и открытые политики означают, что записать и прочитать данные может любой, у кого есть ключ. Хеши паролей синхронизируются, чтобы аккаунты сохранялись в любом браузере, сообщения уходят зашифрованными.

При запуске приложение читает состояние из Supabase и объединяет его с локальным: аккаунты и данные не теряются, но сессия остаётся локальной. Изменения отправляются обратно с задержкой 600 мс. Если Supabase недоступен, приложение продолжает работать на `localStorage`.

## GitHub Pages

Сайт готов к размещению на GitHub Pages: сборка не нужна, все пути относительные, роутер работает через `#`.

1. Залей папку проекта в GitHub-репозиторий, ветка `main`.
2. Зайди в **Settings → Pages → Build and deployment → Source** и выбери **GitHub Actions**.
3. При первом push в `main` workflow `.github/workflows/deploy.yml` сам соберёт и опубликует сайт.
4. Адрес будет вида `https://<логин>.github.io/<репозиторий>/`.

Автообновление: после каждого изменения в коде достаточно выполнить `powershell -ExecutionPolicy Bypass -File .\sync.ps1`. Скрипт сам коммитит и пушит в `main`, а GitHub Actions автоматически перевыкладывает сайт.

Файл `.nojekyll` отключает обработку Jekyll, чтобы ассеты и ES-модули публиковались как есть. Supabase доступен и с GitHub Pages: запросы идут с origin `https://<логин>.github.io`, CORS у Supabase по умолчанию разрешён.

Помни: теперь данные доступны всем, у кого есть публичный ключ из `src/config/supabase.js`. Для реального проекта нужно включить Supabase Auth и закрыть политики RLS.

## Локальные версии

В папке `versions/` хранятся снимки проекта с номерами `0.1`, `0.1.1`, `0.2` и так далее. Они нужны как запасной вариант: если что-то сломается, можно просто открыть последнюю рабочую папку. В Git и на GitHub Pages эти снимки не попадают.

Создать версию:

```
powershell -ExecutionPolicy Bypass -File .\snapshot.ps1 -Version 0.1.1
```

Текущий номер записан в `versions/CURRENT.txt`. В каждой папке есть `VERSION.txt` с датой и коммитом Git.
